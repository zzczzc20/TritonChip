      README §6

      可见性：ArchBench 对 agent 完全隐藏

      目前（harness 搭建期间）agent 看不到任何一个点，也看不到定义点的代码：没有 id、形状、代码、结果，也没有能推出点的东西。任务说明是"考纲"，按设计只写负载类别、判分方式和预算。

      拆成验证集和终测集两套是提议，尚未决定（O18）；任务和评测器已经按两套实现。
      点集agent 看得到点吗agent 拿得到结果吗由谁测
      agent 自己的测试能，它自己写的全部它自己的 sandbox
      验证集（隐藏）不能只有汇总，限次评分服务、慢档的上板阶段（都在计划中）
      终测集（隐藏）不能永远不能终评，在 agent 停止之后
      为什么要两套隐藏集

      能反复拿到分数的集合会被慢慢拟合；而且候选自己的编译器一定会处理被测的点，可以把看到的东西编码进时序里。限次和只给汇总能把这条通道压窄，只有在 agent 停止之后才运行的终测集能把它彻底关上。

      汇总里有什么

      点数、通过数、通过点的几何平均加速比、fast_1（全部点中既通过又快于 base 的比例）。没有点名、形状、周期，也没有报错原文："unsupported shape 64×128" 这样的报错本身就是题目。

      怎么藏、怎么交付

      ArchBench 留在开发者的仓库里照常维护；导出工作区时去掉它和泄露审计列出的文件；评测器和服务测的是含隐藏包的 base。交付时拆成公开包和隐藏包。harness 只定义可见性，不另造 benchmark。hide 条目一个文件都匹配不到时，导出直接失败。

      隔离是用什么实现的

      每个 run 都在测试主机上起几个 Docker 容器：agent 容器本身断网，只能通过一个只读挂载的 Unix socket 找到网关；评测在另一个没有凭证的容器里做。FPGA 两台 worker 上的沙盒还在计划中（虚线框）。

      边界用什么实现具体设置怎么验证状态
      容器Docker（rootful；rootless Podman 计划中），每个 run 一个容器，provider.py。只挂 bridge.py 一个只读文件，不挂存放任务包的 harness 目录（2026-10-15 修复）--network none、--cap-drop ALL、no-new-privileges、--read-only、--user 1000:1000、--init、CPU/内存/进程数限额、tmpfs、默认 seccomp、无设备doctor 金丝雀容器；tests/test_runner.pydone

      README §12

      FPGA 服务：由 agent 决定用不用，时间有上限且真实执行

      先用便宜的估计器（沙盒里的性能模型、正确性模型、映射到 FPGA 的初步综合），让 agent 很少需要真正跑 FPGA。FPGA 服务只在需要真实时序和资源时才用。

      档执行什么大约返回状态
      快档整器件 out-of-context 综合 + 时序，flow/synth/vivado_ooc.sh tnca_fpga_top <period>，按被评分的 profile（含候选的改动）传参数25 分钟状态；目标周期下的最差 slack 和推出的频率；最差路径（agent 自己 RTL 里的起止点）；资源 LUT/FF/DSP/BRAM/URAMin progress
      慢档经 FPGA harness 实现（package、link、判定时序与 DRC），再在验证集上做上板阶段数小时时序收敛（WNS、TNS、失败端点）；资源；上板阶段只给汇总，不给逐点记录和日志planned
      怎么限制
      • 每个 run 一份 FPGA 时间预算，按 worker 实际用时扣
      • 同一时间每个 run 只能有一个 FPGA 请求
      • 最长耗时超过剩余预算的请求直接拒绝
      • 任务到截止时间就杀掉，已用时间照扣
      • 排队时间不扣 FPGA 预算，但 run 的墙钟照走
      在哪里跑、怎么隔离
      • build worker：所有构建。容器内无网络，Vivado 只读挂载，只有任务目录可写，没有 home
      • card host：只做上板。候选的编译器在这里运行，所以放进沙盒：无网络、系统只读、只给卡的设备节点，看不到任何人的 home、harness 状态和编译缓存
      • 卡是共享的：上板需要约定时间窗口（O14）；换人之前重新烧卡或清空显存，不让一个会话读到另一个会话留下的数据
      • 候选 RTL 先做检查：`include、$readmem*、$fopen 里不能有绝对路径或 ..
      要知道的
      • 综合估计偏乐观：这个设计布线后的最差路径约为综合估计的 1.6 倍。快档用来排序和筛选，最终频率以慢档为准
      • license：已实测，U280/U50 器件的 OOC 综合不需要 license，断网、license 完全藏住也能跑（有对照组证明确实藏住了）。真实单元 tnca_matrix 1.8 分钟综合完。下一步是做真正的容器镜像
      • 版本：仓库的 flow 把 U280 固定在 Vitis 2023.2（O13）
