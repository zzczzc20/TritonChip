# Three-core address-path audit at the image source (git 54249f7)

Image a88ebdf5 (B40, UUID 1bada9db-…, 90 MHz) was linked from git commit
`54249f7f7ac0cf8f5d1b82d8e63a3046d27522d3` plus `image.tcl` (attempt03). The
77 RTL files on the FPGA host (`~/tnca_src_r40_attempt03_54249f7`)
hash-equal `git archive 54249f7` (0 mismatches), rechecked read-only in
`rtl-source-check.json`. No device was opened for this check. The frozen Stage 1 tree
(r41s1 `21d09f3`) differs from it in 7 RTL files: `tnca_vector_fpu.v`
(FPU only) and six SLR-timing edits (`tnca_line_axi.v`,
`tnca_memory_mode.v`, `tnca_multicore_mmio.v`, `tnca_idle_host_mux.v`,
`tnca_tile.v`, `tnca_top.v`) that register control copies; none narrows an
address (the frozen `tnca_line_axi.v` keeps 64-bit `base_q`/`bound_q`/`offset`).

Image parameters (`evidence/r40/v2/convergence/attempt03/image.tcl`): 3 cores
in a 3x1 mesh, 3 outlets, SETS 32 / SET_W 5 / WAYS 8, `MEM_BASE` (local
limit) 0x20000, `TMU_BASE` 0x7FFF0000 (default, not overridden).

Width legend: **64** = full 64-bit address carrier. Line numbers are in the
54249f7 tree.

## Address decomposition and local selectors

These short fields select within a word, line, page or local RAM; they are
not substitutes for the full address/tag above. All references are still to
54249f7. Including them makes explicit which low bits are omitted where.

| Field | file:line | Width | Limits 8 GiB? |
|---|---|---|---|
| instruction immediate | `rtl/core/tnca_decoder.v:115–120` | 16 / 24, extended to 64 | no: relative offset; scalar base is 64-bit |
| LSU byte-in-word offset `boff` | `rtl/core/tnca_lsu.v:198–200` | 3 at MEM_DW=64 | no: word address retains the other bits in a 64-bit value |
| cache line offset / set / word select | `rtl/nuca/tnca_nuca_slice.v:183–185,212–214` | 6 / 5 / 3 | no: 53-bit full tag plus 5 set bits plus 6 line-offset bits cover all 64 bits |
| same-line request/MSHR compare | `rtl/nuca/tnca_nuca_slice.v:413,641` | 58, addr[63:6] | no: only the six byte-within-line bits are omitted |
| TMU register offset | `rtl/nuca/tnca_nuca_slice.v:863,866` | 12, addr[11:0] | no: used after the full upper-52-bit page comparison |
| TXF VRF register/lane selectors | `rtl/core/tnca_tensor.v:429–431,446` | 32-bit window offset, 8-bit register, 4-bit lane | no: register-file addressing only; memory `ld_g`, `ld_wlo`, `st_g` stay 64-bit |
| on-chip code RAM word index | `rtl/tnca_multicore_shell.v:135` | address >> 3 under 128 KiB guard | no: only the local code region uses this RAM |

AXI IDs, NoC source/destination coordinates and cache way/slot IDs are
transaction/routing selectors, not memory-address identities. Their widths
do not select the window size. `fpga/u280_multicore_hbm.cfg:3–5` supplies
all 32 PCs to each AXI master. Host BO lengths and offsets use
`ctypes.c_size_t` (`python/tnca/backends/u50.py:1018,1024–1028`), 64 bits on
the FPGA host; `bo_write`/`bo_read` bounds are at lines 1220/1233.

## Executed checks

* `tb/fpga/tb_line_axi_hbm8.v` on both the image `tnca_line_axi.v` and the
  frozen one: 35/35 for BO bases 0, 4 GiB and 2^64-8 GiB (legal edges at
  0, 2 GiB, 4 GiB, 6 GiB and 8 GiB-64 issue exactly `base + offset` on AR/AW;
  8 GiB, 12 GiB, 16 GiB, below MEM_BASE, unaligned and a 2^64-wrapping
  aperture are refused with no AXI transaction). Mutants (bus address cut to
  33 bits, window limit removed, alignment check removed) are each caught.
  The 33-bit mutant passes with BO base 0 -- an 8 GiB window at base 0 uses
  physical bits 0-32 -- and is caught at base 4 GiB.
* The full three-core board top (`tnca_multicore_hbm_xo`) of 54249f7 with
  the image cache geometry, simulated with a sparse 8 GiB window (README).
