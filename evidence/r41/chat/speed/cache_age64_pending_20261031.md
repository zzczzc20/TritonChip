# Experimental 64-lookup cache aging

The isolated candidate uses the non-default `TNCA_CODE_CACHE_POLICY=lfu-sqrt` and ages lookup frequencies every 64 rather than 256 calls. The [patch](cache_age64_experiment_20261031.patch.gz) is not merged. The [synthetic DP TLM trace](cache_age64_synth_20261031.tgz) replays mapped loads, not a full model. In 11 steady rounds LRU → candidate: 203 → 132 loads, 202 → 132 evictions, 2,634,816 → 2,145,088 uploaded code bytes; the exact DP probe had 0/2,816 bit mismatches, 7,271 cycles and 0.1002197265625 instructions/MAC per launch for both. The [FP8 and compiled-graph suite](cache_age64_suite_20261031.tgz) passed 16/16 with bitwise exact outputs. The [default-code audit](cache_age64_audit_20261031.tgz) compared 113/113 unchanged, with zero changed or uncompared. The actual model comparisons remain pending. No board result is claimed.

The [one-layer VL model TLM](cache_age64_vl_model_20261031.tgz) compares LRU → age64 under the same DP profile. Prefill: 28 → 28 launches, 543716965 → 529863199 cycles, 23 → 22 physical code loads, 328000 → 239552 uploaded bytes, 0.0472591285 → 0.0472591285 FP8 instructions/MAC. Decode: 25 → 25 launches, 499900292 → 499913579 cycles, 19 → 18 loads, 186176 → 185920 uploaded bytes, 0.4194615682 → 0.4194615682 instructions/MAC. Both outputs compared bitwise over 151936 logits per step, with no mismatches or numerical CPU fallback and no host reads in either measured step. These are reduced-depth TLM results, not board throughput. The Qwen3.5 model comparison remains pending.

The [four-layer Qwen3.5 model TLM](cache_age64_q35_model_20261031.tgz) compared LRU → age64. Prefill: 239 → 239 launches, 2227778949 → 2227980108 cycles, 141 → 139 physical code loads, 1881792 → 1900992 uploaded bytes, 0.0342451794 → 0.0342451794 FP8 instructions/MAC. Decode: 95 → 95 launches, 1436880921 → 1436970630 cycles, 77 → 59 loads, 905152 → 966848 uploaded bytes, 0.4137841797 → 0.4137841797 FP8 instructions/MAC. Two steps of 248320 logits were bitwise identical and no numerical CPU fallback was captured. Decode recorded zero host reads; both prefill executions recorded 33 compilation-time scalar reads from Inductor constant folding. These are reduced-depth TLM comparisons, not board results. The uploaded-code byte increase and small cycle changes remain visible. Matched tests against the final activation-staging source are pending.

The [matched activation-staging VL TLM](cache_age64_final_vl_tlm_20261031.tgz) compared the final cache-candidate compiler/runtime source against the earlier activation-staging control. Launch metadata and compiled code text were identical. LRU → age64 prefill was 28 → 28 launches, 529853540 → 518721293 cycles, 23 → 23 code loads, 328000 → 328000 uploaded bytes and 0.0472591285 → 0.0472591285 FP8 instructions/MAC. Decode was 25 → 25 launches, 489017348 → 479309579 cycles, 19 → 17 loads, 165184 → 164416 uploaded bytes and 0.2593053182 → 0.2593053182 FP8 instructions/MAC. Both 151936-logit steps were bitwise identical, without captured numerical CPU fallback or host reads. This is one-layer uncalibrated TLM, not board throughput. The activation-staging control and candidate source snapshots differ in later guarded hoist code, although their compared compiled kernels are identical; the current branch subsequently incorporated an unrelated TNCA-IR AOT fix outside this Triton path. The matching Qwen3.5 model comparison is still running.


The [matched activation-staging four-layer Qwen3.5 TLM](cache_age64_final_q35_tlm_20261031.tgz) completed. Compiled kernel texts and launch metadata matched. LRU → age64 prefill: 239 → 239 launches, 2206641939 → 2230822400 device cycles, 141 → 138 physical code loads, 1881792 → 1887424 uploaded bytes, and 0.0342451794 → 0.0342451794 FP8 instructions/MAC. Decode: 95 → 95 launches, 1344816549 → 1378763635 device cycles, 77 → 52 physical loads, 716224 → 636864 bytes, and 0.2536279297 → 0.2536279297 instructions/MAC. Both 248320-logit steps were bitwise identical with no captured CPU numerical fallback. Each prefill had 33 compilation-time host reads; decode had zero. Despite fewer decode loads and bytes, this single reduced-depth TLM observation regressed decode device cycles by about 2.5%; it does not establish a board improvement. The candidate is not merged or queued for board testing.
