# Inline TensorMap publication after SPMD hoisting

Resolved the default-local-memory wide-head attention sequence failure without changing the image, tensor addresses, workload, precision or tolerance. All fourteen standard Torch SDPA cases now pass on the same single-core hybrid U280 image with the default heap policy, including the formerly failing D32 decode after the nine earlier cases. This is functional validation, not R40-08 performance/final multicore acceptance.

The old 512 KiB RAM snapshot reproduces the failure on both the board and RTL. The captured request trace reads TensorMap base word 0x20200 before the LSU store of 0x20600 reaches that address; DMA subsequently reads low code addresses starting at zero. Input tensors and generated code were correct. Merely clearing output or the pre-argument gap does not fix the snapshot. Clearing the preceding code hides the erroneous K reads sufficiently to meet this small numerical tolerance, so that is negative diagnostic evidence, not a fix.

RCTX SPMD hoists invariant TensorMap words and can leave the dynamic base store immediately beside its descriptor snapshot. The transform now inserts a device release fence before snapshots of maps it writes, in both hoisted and per-program regions. Read-only host descriptors receive no additional fence. The legacy path with the transform disabled is unchanged: the original B39 artifacts still match 447/447 byte for byte.

Validation: complete default-policy board sequence 14/14; compiler unit 96/96; real Triton-to-RTL 7/7; B39 artifact contract 447/447. The new publication test exercises three successive dynamic map bases with a delayed store requester and a stale nonzero initial base; removing publication makes it fail. It also covers invariant maps and read-only host maps. MLIR tests were unavailable in this jump-host checkout (tnca-opt absent), as recorded in compiler.log; no MLIR PASS is claimed.

The compressed snapshot preserves exact original bytes. To replay the old bug diagnostically, decompress snapshot.bin.gz to /tmp/r40_sdpa_failure_ram_snapshot.bin, copy snapshot.json to /tmp/r40_sdpa_failure_ram_snapshot.json and run r40_sdpa_snapshot_replay.py exact from a source checkout with the recorded hybrid image loaded. This launches the captured old machine code directly and is not an accepted performance path. r40_sdpa_snapshot_replay_any.py supports sim-file with a prepared core-vrf-sync-v5 bench. Captured scripts preserve their original temporary paths; they are diagnostic reproductions, not product APIs. old_rtl_requests.log.gz records the faulty request order.

sources.json records the board source overlay on f2b081e and the actual unchanged xclbin SHA256. Unit/compiler regression ran on a complete archive of 421a841 with the same rctx_spmd.py overlay. Final FPGA timing/multicore and application performance gates remain pending. The frozen v2 contract is unchanged.
