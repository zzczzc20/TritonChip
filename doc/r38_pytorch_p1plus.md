# R38 PyTorch P1+: PyTorch Support via Inductor

Version 0.1, 2026-09-22. Status: **IN PROGRESS / NOT ACCEPTED**.
Upstream: [R38 roadmap §12](r38_isca_roadmap.md), [Stage 1](r38_stage1_tasks_and_acceptance.md) (replaces "P0/P1 small graphs" in S1-10).

## 0. Decision

Do not implement a handwritten ATen-to-kernel mapping for P1; instead, route directly through Inductor: `torch.compile` → Triton kernels generated by Inductor → TNCA. Rationale: writing manual mappings before transitioning to Inductor inevitably leaves two separate execution paths.

Scope limitation: Guarantee correctness only for a **feature subset and small shapes**; large shapes and broad coverage will follow once hardware execution is available (Stage 2).

## 1. Principles

1. **Minimize custom implementation**: Rely entirely on upstream PyTorch/Inductor/Triton for graph capture, decomposition, fusion, scheduling, and Triton code generation; implement only what upstream cannot provide.
2. **Single compilation path**: The Triton plugin compilation stage and `tnca.aot.compile_aot` call the exact same TTIR→TNCA function; the `.tnca` artifact produced for identical kernels and arguments across both entry points must be **byte-identical**.
3. **Single execution path**: All executions go through `tnca.runtime.Session`, without introducing a separate runtime.
4. **No silent fallbacks**: Any computation executed on the CPU must be detected and reported; acceptance test cases require zero CPU fallback.
5. **Strict CI**: Every change must keep all existing correctness tests passing with unchanged execution cycles (see §4).

## 2. Architecture

```text
torch.compile(model)            ← Upstream Dynamo / AOTAutograd / Inductor (unmodified)
   │  Inductor config: cpu_backend="triton"
   ▼
Inductor-generated @triton.jit kernel + wrapper   ← Upstream
   │  triton.compile(...)  ← Upstream JIT / cache / parameter specialization
   ▼
Triton backend plugin (entry point triton.backends: cpu; tnca prior to 2026-10-08)    ← Thin custom layer
   compiler.py : BaseBackend, stages = ttir (upstream make_ir) → tnca (shared _lower_ttir)
   driver.py   : DriverBase, target=GPUTarget('tnca'), launcher → Session
   ▼
tnca.runtime.Session → RTL (core-sim / core-xpose-v1)   ← Existing
```

Tensor residency: In Stage 1, tensors are host (CPU) torch tensors. The launcher deduplicates by storage, uploads the storage of each argument to a device buffer, launches the entire grid, and downloads the storage back. This defines an explicit host round-trip boundary; keeping intermediate tensors on the device belongs to subsequent optimizations (PrivateUse1 device in P2) and is outside this stage.

## 5. Implementation and Status (2026-09-22)

| Component | Location | Description |
|---|---|---|
| Shared lowering | `tnca.aot._lower_ttir`, `tnca.aot._seal` | Shared between `compile_aot` and the plugin; refactored 447 R37 artifacts are byte-identical to the frozen baseline |
| Triton plugin | `python/tnca/triton_backend/` (entry point `triton.backends: cpu`; Inductor recognizes this key as the CPU Triton backend to generate tensor descriptors for CPU tensors) | compiler: TTIR enters shared lowering unmodified; driver: launcher uploads/downloads torch CPU tensors per storage and executes via `Session`; `libdevice` provides only functions with exact semantics |
| Inductor integration | `tnca.inductor.configure()` | Entirely via upstream extension points: `cpu_backend="triton"`; registered pointwise/reduction heuristics for device `cpu` (block ≤ 16); single 16×16×16 mm template config; `persistent_reductions=False`; `compile_threads=1` |
| Tests | `make r38-torch` | `plugin_identity.py` (O0/O1/O2 text segments byte-identical), `triton_native_run.py` (149 R37 cases launched natively via `kernel[grid]`), `torch_tests.py` (originally 12 graphs; expanded to 23 graphs + 1 device-assert trap check during §6 hardening) |

Compiler additions made for this purpose (all belonging to what upstream cannot provide and must be implemented locally):

- `arith.maximumf/minimumf` reduction: Constructed using ordinary max reduction with specified semantics plus NaN detection (`_reduce_vec`).
- `llvm.intr.assume`: Explicitly lowered to a no-op (with `index_opt`, non-negativity is tracked).
- Fixed condition code spelling for `arith.cmpf uno` (`u` → `uo`), which was never reached before.

Known limitations:

- Block size capped at 16 (the compiler does not yet support wide tensors spanning multiple vector registers), representing the small-shape limitation of this stage.
- Tensors are uploaded and downloaded on each launch, without device residency.
- The plugin's Triton cache key covers compiler source files; `TNCA_PROFILE` / `TNCA_OPT_LEVEL` enter the options hash.
- JIT specialization alters the TTIR of certain kernels, so roughly half of native launches match AOT baseline cycles, while the remainder differ but remain numerically correct; byte-identical guarantees apply to identical TTIR.
- Kernels with asynchronous tensor transfers do not declare pointer aliasing, so overlapping arguments are still refused by the runtime.

## 6. Hardening: ArchBench-Driven End-to-End Pipeline (2026-10-07)

Decision (2026-10-07): ArchBench is built upon PyTorch ([archbench/](../archbench/README.md)), evaluating performance against GPU on identical PyTorch programs compiled via each platform's respective `torch.compile`. Exercising the full end-to-end pipeline across ArchBench's tiny/small tiers (52 points: 16 LLM operator families, general operators, LLaMA prefill/decode, GPT-2 block, MLP, ResNet block) uncovered and resolved the following gaps:

**Inductor Integration (`tnca.inductor.configure`, strictly using upstream extension points)**

| Gap | Resolution |
|---|---|
| `scaled_dot_product_attention` on CPU tensors becomes an `aten._scaled_dot_product_flash_attention_for_cpu` host call | Added upstream math decomposition (used by `torch.export`) to Inductor's decomposition table; affects CPU tensors only |
| Conv template configurations start from 64×256 | Registered device `cpu` config heuristic offering only a single 16×16×16 configuration |
| Reduction kernels process multiple rows per program, turning per-row values (argmax index, embedding token ID) into 2-D blocks | Reduction heuristic `XBLOCK = 1`: one program per row, reduction dimension chunked at 16 |
| Inductor FX graph cache key omits registered decompositions/heuristics, causing stale graphs with host fallbacks to be reused | Disabled `fx_graph_cache` and AOTAutograd cache; kernels remain cached by Triton (key covers compiler source) |
| Under `max-autotune`, Inductor times epilogue fusion; CPU device interface cannot time execution | `benchmark_epilogue_fusion = False`: disables timing benchmarks, ensuring compilation output is independent of host speed |

**Compiler (TTIR → TNCA IR)**

| Gap | Resolution |
|---|---|
| `tl.device_assert` (inserted by Inductor for every indirect index) | Real check: triggers `TRAP_USER 0xA55E7` if any active lane is false, including 2-D conditions |
| `int64` tensors (token IDs, argmax outputs) | Extended `wide.py`: load/store/compare/select/broadcast for 1-D and single-row 2-D blocks, exact per-lane; narrowing check before 64-bit offsets enter pointers (`TRAP_USER 0xA5564` on out-of-range, no wrap-around) |
| Boolean constant `arith.constant true` lacked type suffix, causing constant matching to fail and rendering floating-point constants unreadable | Corrected pattern matching (latent bug, previously triggered by fp16 argmax) |
| Multi-operand reduction/scan only accepted 1-D | Single-row 2-D block `(1, n)` along axis 1 treated equivalent to vector register lanes |
| GEMM template with M = 1 (all decode projections) has row stride 0 for A, which TensorMap cannot represent | Single vector load broadcast across rows, repacked into MMA identical to compute tile |
| **2-D boolean splat treated as index term**: `idx_q < BATCH` merged into store mask masked entire block, so bmm and attention results were never written out | 2-D i1 splats become predicate tiles (latent bug affecting all 2-D stores with scalar condition masks) |
| Loop-carried i1 tile lacked storage | Carried as 0/1 words, compared upon read |
| Tile `tt.bitcast` (Inductor `select_one`) | Same-width reinterpretation, rows unchanged |
| **`[1, 1]` value broadcast along row not unrolled**: flag/index loaded once per program was only in lane 0; `tt.broadcast` to `[1, 16]` directly reused register, so `tl.where(flag, x, 0)` preserved only 1 of 16 elements | Broadcast splats lane 0 across entire row (predicates handled identically). Applied only to `[1, 1]` source: `[R, 1]` derived from 2-D index already has values in each lane, relaxing it would needlessly change 45 R3.7 artifacts; non-uniform `[R, 1]` (R > 1) remains unhandled |
| **Boolean tile select treated predicate registers as vector data**: `acc = tl.where(m, acc \| x, acc)` in Inductor `any` read vector register of same index | Boolean select implemented via predicate AND/OR combinations |
| Boolean-to-numeric conversion (`uitofp`/`sitofp`, `mask.float()`) passed predicate registers to `v.cvt` | First converted to per-lane 0/1 (or −1 for signed) |
| 64-bit sum on single-row blocks (`mask.sum()`) | Reductions in `wide.py` accept `(1, n)` |

**Runtime / Plugin**: Backend selected via environment (`TNCA_BACKEND`, `TNCA_BACKEND_ARGS`), allowing the identical torch program to run on `sim-file`, `fpga-u50-sim`, and `fpga-u50`; `launch_log()` records cycles, program count, hardware counters, and transferred bytes per launch; `TNCA_HOST_TIMEOUT`; `TNCA_LAUNCH=skip` compiles without running; plugin honors `TNCA_KERNEL_DUMP` (writing stages even for failed kernels), with `tools/r38/ttir_lower.py` reproducing lowering outside Inductor.

**Results**: Tiny + small tiers all compile successfully across 52 points (`make archbench-coverage`) with zero host fallback; numerical results for tiny tier on RTL documented in [r38_stage1_status.md](r38_stage1_status.md). Cycle counts matching identical simulation profiles point-by-point via card register protocol (`fpga-u50-sim`, sharing the same `U50Backend` and `tnca_fpga_top` as physical hardware).

Single-query (decode, M = 1) attention previously failed numerically due to the last three boolean defects above (flags indicating whether the row has finite scores in SDPA decomposition); verified post-fix in status document.

Still uncovered: Tensor block width > 16, int64 operations on multi-row blocks, full RTL simulation of small tier models (single run takes hours to tens of hours, deferred to physical FPGA), device-resident tensors (P2).
