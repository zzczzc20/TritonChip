# Synthesis and PPA proxies

Generated by `make synth` (`flow/synth/synth.py`), Yosys 0.52, no PDK.

## What these numbers are, and are not

There is no process library in this repository, so nothing here is an area,
timing or power result. Two proxies are reported:

| Metric | Definition | Good for | Not good for |
|---|---|---|---|
| **gates** | cell count after mapping to `AND/NAND/OR/NOR/XOR/XNOR/MUX/AOI/OAI` | comparing random logic between modules and across commits | anything storage-heavy; register files map to flops here but belong in SRAM macros |
| **depth** | longest topological path between registers, in gate levels (`ltp -noff`) | spotting combinational paths that cannot possibly close timing | an actual delay number; real delay depends on drive strength, wire load and the library |
| **flops** | sequential bits | sanity-checking that state matches the architectural spec | area, since flop area varies by several times across cell flavours |

The depth budget used in the report is **50 levels**, from a 1 GHz target and a
rule-of-thumb 15–25 ps per gate level with clock overhead allowed for. A module
over budget is reported as a finding, not hidden, and it does not fail the
build — synthesisability does.

## What measuring already changed

Two structures were rebuilt because the numbers said so, not because they
looked wrong. Both are §6.2 of the architecture document applied literally:
decide the arithmetic after looking at what it costs.

### One multiplier per lane instead of two

`v.mulh.s` and `v.mulh.u` were written as `$signed(x)*$signed(y)` and `x*y`,
which is two independent multiplier arrays per lane. The signed high half is
derivable from the unsigned product:

```
x_s * y_s = x*y - 2^N*(x[N-1] ? y : 0) - 2^N*(y[N-1] ? x : 0)   (mod 2^2N)
```

The correction terms are multiples of 2^N, so they touch only the high half and
cannot borrow out of the low half — two conditional subtractions replace an
entire array.

| | before | after |
|---|---:|---:|
| `tnca_scalar_alu` gates | 33,783 | **26,017** (−23 %) |
| `tnca_vector_alu` gates | 205,205 | **163,101** (−21 %) |

Depth went the other way for the scalar unit (112 → 128 levels), because the
correction sits after the multiply. That is an acceptable trade only because
the multiplier has to be pipelined anyway; once it is, the correction lands in
a later stage and costs nothing. Recording it here so the trade is not
rediscovered as a surprise.

`tb/core/progs/t06_alu.s` covers the derivation with 186 randomised cases
weighted toward sign boundaries, and the test was confirmed to fail when the
correction is removed.

### One shuffle crossbar instead of five

`v.shuffle.xor`, `.up`, `.down`, `.rotate` and `v.permute` differ only in which
source lane each destination lane reads. Written as five separate selects they
synthesise to five independent 16-to-1 crossbars of 32 bits. Computing the
source index per pattern and sharing one crossbar is the same function at
roughly a fifth of the mux area. The clamping forms express their clamp as
"read your own lane", which is just another index.

The same pass replaced six independent comparator trees (`min.s`, `max.s`,
`min.u`, `max.u`, `v.cmp`, `v.sub`) with one subtractor per lane: the borrow out
of `x - y` is the unsigned "less than", and the signed form differs from it only
when the operand signs differ, in which case the answer is `x`'s sign bit.

| `tnca_vector_alu` | gates | depth |
|---|---:|---:|
| as first written | 205,205 | 102 |
| one multiplier per lane | 163,101 | 101 |
| + shared crossbar and comparator | **145,334** | **99** |

**−29 % area for identical behaviour**, verified by the same 266 vector checks
(`t01_vector` plus `t06_alu`) before and after. Depth is essentially unchanged,
which is the point: this was area spent on duplicated structures, not on
anything that was buying speed.

## Findings

### 1. The FP datapath cannot be clocked at 1 GHz as written

207 gate levels is roughly 3–5 ns of logic. The Stage-1 core is built with
every execute-stage unit at single-cycle latency, which was the right choice
for establishing ISA and memory semantics, but it puts the whole FMA —
alignment shift, 24×24 multiply, 88-bit add, leading-zero normalisation,
rounding — between two registers.

The fix is a three- or four-stage cut, and the core is already shaped for it:
`tnca_core` has a per-instruction notion of latency and an out-of-band
completion path, so raising FP latency means adding a writeback reservation
shift register and nothing else. This is the first Stage-1b task.

A useful comparison: `tnca_fp32_fma` is only 6,781 gates. The FP problem in
this design is **depth, not area** — which is the opposite of the intuition
that says "floating point is expensive". Sixteen lanes is about 109 k gates,
real but affordable; sixteen lanes at 207 levels is unbuildable at the target
frequency.

### 2. The scalar multiplier does not belong in a single cycle either

26,017 gates and 128 levels for `tnca_scalar_alu`, against 682 for the whole
decoder, is almost entirely the 64×64 multiplier. The scalar unit's actual job
is address arithmetic and loop counters, so the options are, in order of
preference:

1. pipeline the multiplier over 3 cycles and leave the rest of the ALU at one;
2. narrow `s.mul` to 32×32→64 natively and expand the 64-bit form in software,
   which matches the architecture document's position that FP64 and integer
   division are library, not hardware (§11.3);
3. leave it, and accept that scalar multiply sets the clock.

Option 1 is the plan. Option 2 would be an ISA change and needs a real workload
argument first.

### 3. The integer vector unit is still the largest block in the core

Even after sharing the multiplier, the crossbar and the comparator, the 16-lane
integer unit is larger than the entire 16-lane FP array. The remaining cost is
structural: every operation is computed for every lane and the answer is
selected at the end, so the shifters (`shl`/`lshr`/`ashr`), `clz`, `popc` and
the reduction tree all exist simultaneously.

The next reductions, in order of value:

1. one funnel shifter per lane serving all three shift directions, with
   left shift done by input and output bit reversal;
2. `clz`/`popc` shared with the reduction tree's adder network rather than built
   per lane;
3. if the vector RF moves to banked SRAM with an operand collector (§5.3), the
   unit can go multi-cycle for the rare operations and drop them from the
   parallel array entirely.

None of these change the ISA.

### 4. The register files must not stay as flops

`tnca_scalar_rf` is 31,033 gates for 8 kbit of state — that ratio is the cost
of three asynchronous read ports built out of multiplexer trees. The vector
file is the same structure at 32 KiB in the reference configuration, which is
not something to build from flops at all.

The architecture document is explicit about this (§5.3): banked SRAM, 16 banks
of 64 bit, 1R1W each, with an operand-collector front end and a stated port
budget, sized *before* the arithmetic is sized. Stage 2 replaces
`tnca_vector_rf` accordingly. Until then the gate number for that module should
be read as "this is why the banked version exists", not as a design estimate.

### 5. Decode is cheap, which is worth keeping

682 gates and 17 levels, including the full reserved-field legality check that
ISA §2.3 requires. Enforcing the encoding contract costs almost nothing, so
there is no performance argument for relaxing it later.
