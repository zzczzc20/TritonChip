# Parallel SFU candidate

Memory-path improvements expose SFU serialization in standard torch silu. `tnca_sfu` now has an opt-in LANES parameter (default one), also exposed as SFU_LANES in the core and vector FPU. Each group instantiates the same existing generated exp2, reciprocal, reciprocal-square-root and log2 pipelines, with unchanged LAT. Only the number of serial lane passes changes. Input vectors and function selection remain latched on launch. Padding supports lane counts that do not divide VLEN. Integration above the core remains pending; no image enables this option yet.

`tools/r41/sfu_parallel_tests.py` passes 160 vectors per configuration for 2, 3, 4 and 8 slices. Each vector compares all 512 output bits against the original serial sequencer. Cases cover all four functions, random bit patterns, zeros, infinities, NaNs, subnormals, changed inputs during execution, completion pulse width and reset interruption. The measured RTL completion cycles are 23 for one slice and 15/13/11/9 for 2/3/4/8 slices. The default one-slice implementation also passes the existing tb_sfu_core reference suite: 1,042 batches, 16,672 vectors and zero failures. Generated arithmetic RTL was not changed.

The free four-slice routed screen runs on acf3019 under ~/r41_hbmbw_sfu_v1, using the shared Vivado slot wrapper with an 8 GiB free-memory guard and four tool threads. It targets one SLR at 10 ns. The unit screen does not prove combined core timing or image fit. No full image build or board open is involved. Raw functional logs are retained here; physical reports will be added on completion.
