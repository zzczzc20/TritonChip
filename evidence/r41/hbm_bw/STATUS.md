# HBM bandwidth status

Updated: 2026-10-26 UTC.

## Goal and current evidence

The memory-system design target remains 100 GB/s. HANDOFF section 7 makes several-times standard torch operator speedups on the board, with unchanged numerics, the actual acceptance gate. No candidate image or board speedup exists. Isolated stream bandwidth is insufficient. See `end_to_end.md` for the revised audit and `operator_baseline.json` for the baseline-only comparison ledger.

The source audit and existing R40 board/model evidence establish an upstream bottleneck. Three 64-bit core request paths admit at most 2.4 GB/s at 100 MHz, before protocol overhead. Three 256-bit outlets provide 9.6 GB/s in each AXI data direction. The prior ports experiment measured no gain from one to three outlets. Its model attributed contention to the home engine and core dependency waits; this attribution is not a new board measurement.

## Engineering direction

The copy-only stream candidate is a partial path, not an end-to-end acceptance architecture. Preserve its measured unit evidence and software integration while prioritizing the real NoC/NUCA/LSU/RF operator path. The fixed 64-bit NI and word-data packet fields require coordinated changes; simply raising LSU or AXI widths is insufficient. Runtime peer-CU, ownership, synchronous events and native copy dispatch now pass software fixture tests, including real torch tensors on GB10. These tests do not execute the board and establish no speedup. Do not launch a full image solely for stream-copy bandwidth.

## Wide NoC boundary and LSU area decision

The 8-unit/512-bit general LSU bank requires 440,741 LUTs and 186,131 FFs per core. Three banks alone exceed the chip's 1,303,680 LUTs, so this replication is rejected for the image. Completed utilization evidence is in `lsu_bank/synth_wide8/`; the corrected run completed with exit zero and wrote its checkpoint. Next implement a shared contiguous-vector planner with finite response slots and the original narrow path for complex/MMIO/atomic accesses, rather than cloning the general planner.

Parameterized core/slice NIs now preserve the default 216-bit layout and carry 512-bit data in a 720-bit packet. Eight real three-node mesh tests pass, including full data/mask/tag/opcode checks, canonical legacy encoding and destination backpressure. No-stall tests accept 768 packets in 768 cycles. This is an RTL transport boundary result with echo endpoints, not cache/home or HBM performance. The tile/top still use narrow defaults; complete integration and physical receiving-stage capacity remain pending. See `wide_noc/README.md`. No full-run allocation or card access was consumed.
