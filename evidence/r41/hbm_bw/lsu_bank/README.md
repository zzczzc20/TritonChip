# Finite multi-command LSU candidate

`rtl/core/tnca_lsu_bank.v` implements the finite 4/8-unit candidate that the coupled model identified. Existing one/two-unit core configurations retain their original modules; core LSU_INFLIGHT of four or eight selects the bank. It keeps one memory issue port and one completion/RF writeback port. A new ordinary command starts only when an idle unit exists and every older busy unit has finished issuing its beats. Replies may arrive in any order. Atomics require complete quiescence and block younger admissions until completion; fences retain the all-units-idle meaning of req_ready.

An age queue chooses the oldest **ready** completion, allowing an unrelated destination to complete while an older reply is delayed, as the original pair permits. A backpressured completion holds its selection and payload until acknowledgement. A unit cannot be reused until its completion retires. The queue supports simultaneous admission/retirement without wrapping age counters. Request tags partition the fixed four-bit LSU identity space into unit and beat fields. Four units use four beat slots each; eight units use two each. A simulation guard refuses unsupported geometry rather than silently aliasing outstanding tags.

## Functional evidence

`tools/r41/lsu_bank_tests.py` runs 18 randomized cases: 2/4/8 units, three seeds and both mixed traffic and a long-latency scalar-load stream. Each runs 600 accesses. The reference is the original tnca_lsu_pair with eight slots per unit; the candidate keeps 16 total beat identities. Independent memory agents impose random request backpressure, long port stalls, completion backpressure, response delays and response reordering. The miter compares every accepted memory request's semantic payload (excluding identity tags), every command's completion data/metadata and every final memory word. Mixed cases include scalar/vector/gather loads/stores, all supported scalar sizes, masks, signed accesses, unaligned straddles and atomics. Tags cannot be reused while outstanding; a stalled memory request and completion must remain stable.

All cases pass. Long-latency cases reach exactly 2/4/8 occupied command units respectively, proving capacity was exercised rather than merely instantiated. Eight-unit long-latency loads finish in approximately 9,400 cycles versus the reference's 34,000–35,600 cycles. Mixed narrow-port traffic can regress: eight-unit cases take approximately 18,500–20,800 cycles versus 14,600–15,700 for the reference. This is expected evidence against enabling command replication alone: fewer beat credits per command can hurt vectors while the core port stays narrow. These are RTL microbenchmarks, not torch or board speedups.

Full-bank reset/abort and subsequent successful load recovery pass for 2/4/8 units. An over-capacity eight-unit/eight-slots configuration is refused. The core elaborates with LSU_INFLIGHT=8, LSU_BEATS=2 and SFU_LANES=4; core_elaboration.log records that check. It does not establish core execution timing or numerical acceptance of the original suite.

The first long-latency miter failed because the inherited test's completion lookup assumed a small distance from the oldest outstanding command. Tagged completions can legitimately finish farther ahead under long randomized latency. The new lookup covers all issued, uncompleted commands. The failure log is retained. The completion-hold test and age-queue logic additionally cover real RF backpressure.

## Wide LSU boundary

The first 512-bit synthesis refused a real parameterization defect in tnca_lsu: a response loop expanded to MEM_BYTES and selected beyond each lane's 64-bit result. The corrected response loop is bounded by min(MEM_BYTES, 8), the maximum bytes in one lane. It retains the exact eight-byte default loop. The failure report is retained.

`tb_lsu_wide.v` then passes 112 byte-oracle cases for the real 512-bit LSU, covering scalar sizes/sign extension, vector and indexed accesses, masks, unaligned line crossings and partial stores. It checks the complete memory after every command. Wide atomics are deliberately unqualified: preserving their word semantics across a future wide NI/home interface still requires implementation and testing. The initial wide bench incorrectly asserted completion acknowledgement before valid, violating this LSU's existing handshake; its timeout is preserved, and acknowledgement now follows valid.

The eight-unit 512-bit free synthesis screen completed under ~/r41_hbmbw_lsu_bank_v1 on acf3019 with four tool threads, the shared slot wrapper and a 16 GiB free-memory guard. The corrected run uses units8_width512_v2, launcher PID 2631710; the initial failed run was terminal before retry. This screen determines whether replicating general LSUs is affordable or whether the aligned contiguous vector path needs a smaller dedicated coalescer. Neither synthesis nor functional width tests prove NoC/cache integration, combined timing or 100 GB/s throughput. No complete image run or board access was used.

## Area decision

The corrected screen reports **440,741 LUTs and 186,131 FFs** for one eight-unit, 512-bit bank; synth_wide8/synth_util.rpt is the authoritative completed utilization report. Three copies alone require 1,322,223 LUTs, exceeding the device's 1,303,680 LUTs before adding any remaining core, RF, cache, matrix engine, NoC or shell. Replacing the three existing 25,464-LUT pairs in the 819,109-LUT core candidate gives a lower-bound estimate of 2,064,940 LUTs, even before widening other stages. This design is rejected for the image. Functional correctness does not make its replication feasible. The corrected run completed with exit zero and wrote its synthesis checkpoint; complete timing/DRC/log reports are preserved under synth_wide8/. Area alone is decisive.

The selected next implementation direction is a shared planner for contiguous vectors that fit one cache line, with finite independent metadata/response slots and one RF writeback port. It should coalesce one aligned vector into one 512-bit transaction without replicating eight general gather/straddle planners. Complex accesses, scalar MMIO and atomics need the original narrow LSU path and exact tag/byte-position adaptation. That is part of the complete candidate, not an alternative acceptance criterion. The standard torch compiler must actually dispatch the eligible vector instructions through it; all fallback semantics and the complete downstream cache/NoC path remain required. The hypothetical multi-unit model remains an upper-level capacity study and is not evidence of this unimplemented compact path's performance.
